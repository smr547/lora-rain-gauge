# Requirements

## Purpose
This directory records what the product must do and how satisfaction of those requirements will be demonstrated.

## Scope
It contains User Requirements, derived System Requirements and the verification matrix linking requirements to evidence.

## Does not belong here
Implementation choices belong in architecture documents or ADRs. Requirements should describe required behaviour, qualities and constraints rather than prematurely prescribe solutions.

## Relationships
User Requirements are the starting point. System Requirements will be derived from them, architecture will satisfy them, and verification will provide evidence that the delivered system meets them.

## Status
The User Requirements Specification is currently a draft for User review. System requirements and verification traceability will follow.
