# Architecture Decision Records

## Purpose
This directory records significant engineering decisions and, importantly, why they were made.

## Scope
An ADR should capture the context, alternatives considered, decision, rationale and consequences of a decision that future maintainers may reasonably question.

## Does not belong here
Routine implementation detail and transient development notes do not need ADRs. Current system description belongs in the architecture documentation.

## Relationships
ADRs explain the history behind the architecture and implementation. Architecture documents describe the resulting current design.

## Status
Active. ADR numbering will begin as Version 1 decisions are formalised.
